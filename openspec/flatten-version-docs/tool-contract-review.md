# Tool Contract Review — 34/34 MCP tools vs contract-reality audit (B2.3, Req 14)

## Purpose and methodology

Reuses the review format established by `docs/archive/openspec/tool-promise-remediation/spec.md`'s
"Full audit table" (`| # | Tool | Verdict | Evidence |`), extended with the two
route-cross-reference columns Requirement 12(b) and this change's design (§B2)
require: each tool's **recorded (method, path)** call(s) — mechanically captured by
B1.2's `packages/mcp/src/__tests__/tool-route-map.test.ts` and committed to
`tool-routes.snapshot.json` — and that route's **status** in B2.1's four-way
contract-reality set difference (`packages/server/src/__tests__/contract-reality.test.ts` +
`.allowlist.ts`).

**What each column means:**

- **Recorded route(s)**: every distinct `(method, path)` the tool's handler actually
  issued when driven with synthesized/branch-fixture args (B1.2). Concrete param
  values (`fact_1`, `x`, …) are interpolations of a route template, not literal paths.
- **Route status**: cross-referenced against B2.1's findings for that exact route —
  `real, documented` (registered + in the OpenAPI spec, not flagged), `real, UNDOCUMENTED`
  (registered but no OpenAPI entry — see `contract-reality.allowlist.ts`), or
  `GHOST CALL` (would mean the tool calls a route that doesn't exist — **zero tools
  fall in this category**, see "Headline finding" below).
- **Verdict**: carries forward `tool-promise-remediation/spec.md`'s already-verified
  audit table where unchanged, with an explicit **[drift]** marker on every row where
  this session found the underlying code has changed since that audit (2026-07-27/29)
  in a way the prior verdict does not reflect — checked against current source, not
  assumed. Rows with **[not independently re-verified]** carry the prior audit's
  verdict forward without this session re-deriving it from source; where I could not
  gain enough confidence to state a verdict either way, that is said explicitly rather
  than guessing.
- **Evidence**: file:line or test name backing the verdict.

## Headline finding: zero ghost callers

B2.1's `contract-reality.test.ts` computed `(mcpPaths ∪ cliPaths ∪ sdkPaths) \\ routePaths`
(Req 12's ghost-caller difference) against a **fully-populated** `createApp()` fixture
(all conditionally-mounted route families enabled — federation, tenants/workspaces,
approvals, break-glass) and found **zero** ghost callers across all 34 tools, all 46 CLI
commands, and all ~90 SDK methods. No MCP tool, CLI command, or SDK method currently
invokes a route that does not exist — Chain A's stale-version-prefix bug class (e.g. the
old `export/jsonl` call site) is not present anywhere in the three audited client
surfaces today.
(An earlier draft of this test, using B1.1's own minimal test fixture, produced 44
false-positive "ghost callers" — every one was a conditionally-mounted route family the
minimal fixture never registered, not a real bug. Recorded as a methodology note in this
task's return summary.)

## Notable findings for human review

1. **Zero ghost callers, confirmed mechanically** (see "Headline finding" above) —
   the strongest possible evidence against the class of bug this entire change
   exists to prevent, across all 34 tools.
2. **Four independently re-verified upgrades since the last tool-promise-remediation
   audit** (rows #2, #3, #20, #24): `memory_remember`'s PII/poisoning gates
   (CORE-1/CORE-2), `memory_forget`'s archive-data-loss bug (DB-2), `memory_remind_when`'s
   AND/OR semantics and `conditionEmbedding` population (Requirements 1-2), and
   `memory_decide`'s topic_key normalization (Requirement 10) are all now fixed in
   source, confirmed by reading the actual implementation this session — not merely
   assumed from a stale doc. None of these upgrades is yet reflected in
   `docs/archive/openspec/tool-promise-remediation/spec.md`'s own table, which is a **finding in
   itself**: that audit document is drifting out of date as the underlying code keeps
   improving, the same "docs don't track reality" root cause this whole change exists
   to address, one level up.
3. **`POST /self/edit` (rows #15, #16) is a real, actively-used, but UNDOCUMENTED
   route** — flagged as a genuine gap in `contract-reality.allowlist.ts`, not fixed
   here. Two MCP tools (`memory_self_edit`, `memory_update`) and the SDK's own
   `selfEdit()` method all depend on it having no OpenAPI spec entry at all.
4. **Six tools remain genuinely UNAUDITED with no behavioral change since the last
   audit** (`memory_strategy`* , `memory_workflow`, `memory_skill`, `memory_doctor`,
   `memory_judge`, `memory_purge`) — `memory_strategy` now has a contract test file
   whose contents I did not review this session (marked uncertain, not claimed
   verified); the other five have no dedicated contract test at all.
   `memory_doctor` and `memory_purge` remain the two highest-priority gaps per the
   original audit's own risk framing (error-recovery tool; irreversible hard-delete).
5. **`memory_remind_when` (row #20) — Requirements 1-2 confirmed fixed; Requirement 3
   (delivering triggered content, not just counting it) NOT re-checked this session.**
   Genuinely uncertain whether a fired reminder's `content` is now surfaced back to the
   caller or still only logged as an aggregate count — flagged rather than guessed.
