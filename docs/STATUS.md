# Mnemosyne — Implementation Status

What works today, what is partial and what is not there. Mnemosyne is **alpha**, on the `3.6.x`
line. Statuses come from reading the code and its tests, not from the spec; update a row only when
a code change confirms it.

**As of:** 2026-11-18. Counts below were measured on that date.

## Legend

| Status     | Meaning                                                                 |
| ---------- | ----------------------------------------------------------------------- |
| ✅ STABLE  | Implemented, wired end to end and covered by unit and integration tests |
| 🔶 BETA    | Works on its primary paths; known gaps are listed in the notes          |
| ⚠️ PARTIAL | Part of what it promises is true; the note says which part              |
| 🔴 PLANNED | Not implemented                                                         |

## Security and tenancy

| Feature                                         | Status    | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------------------- | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| RLS + FORCE (`withMnemoTx`)                     | ✅ STABLE | Every transaction sets workspace and actor; the app role is `NOSUPERUSER NOBYPASSRLS`                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Sensitivity ceiling                             | ✅ STABLE | Reads above a credential's ceiling answer 404 (S6); writes above it are refused, `404 sensitivity_above_ceiling` (PRIM-14)                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Users, tenants, workspaces, role → scope        | ✅ STABLE | See [`architecture/MULTI_TENANCY.md`](architecture/MULTI_TENANCY.md)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Agent RBAC and approval gate, scopes            | ✅ STABLE | Policies: `PUT /admin/agent-policy` or `mnemo policy set`; a change applies at once on every replica through Redis pub/sub (`MNEMO_REDIS_URL`), and within about a second without Redis: a trigger logs each policy write in the same transaction (migration 0067) and every replica polls that log each second, which works through pgBouncer in transaction mode                                                                                                                                                                                      |
| Active security detection, GDPR export approval | ✅ STABLE | `POST /export` with `types` answers 400                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Column encryption (confidential, restricted)    | ✅ STABLE | `statement` and `subject` are stored AES-256-GCM under the writing actor's key; every read (GET, lists, recall, export, MCP, dashboard) returns them decrypted to a credential whose ceiling allows the tier, or `[unreadable]` with `redacted: "unreadable"` without a key ring. Found by vector and exact-repeat hash only: full-text search never matches them (`auth-gdpr.integration.test.ts`). Plaintext to external providers: `MNEMO_SENSITIVE_TEXT_TO_PROVIDERS` (SECURITY.md §7)                                                              |
| GDPR crypto-erasure                             | ✅ STABLE | `POST /admin/erasure` (scope `memory:hard_delete`, `confirm` repeats the subject) or `mnemo erase` destroys every encryption key of a user, or one actor's; audited before and after (`auth-gdpr.integration.test.ts`). Rows and embeddings stay; only encrypted columns become unreadable, and reads return them as `[erased]` with `redacted: "erased"` (recall leaves them out)                                                                                                                                                                      |
| Scoped keys (`MNEMO_SCOPED_AUTH=1`)             | 🔶 BETA   | Scoped-scheme `mk_*` keys verify against `mnemo_scoped_api_keys`; the keys `/admin/keys` mints keep working in that mode. `POST /admin/scoped-keys` issues, rotates and revokes `mk_live_`, `mk_sess_` and `mk_admin_` keys (CLI `keys scoped`, client-ts); an `mk_admin_` key gets a TOTP secret and its issuer's user, so the two-person gate works with it. gRPC refuses them                                                                                                                                                                        |
| PII detection (regex and NER layers)            | ✅ STABLE |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| mTLS and service JWT, consensus                 | ✅ STABLE |                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Federation (signed sync between servers)        | 🔶 BETA   | Two servers pull from each other, a signed service JWT per pull (`MNEMO_FED_PEER_ID`, `MNEMO_FEDERATION_PRIVATE_KEY`), over HTTP or behind nginx with mTLS (`MNEMO_FED_CLIENT_CERT_FILE`/`_KEY_FILE`, `MNEMO_FED_CA_FILE`). Peers (0061) and sync jobs (0063) live in Postgres. A sync pages on from its last cursor; edits arrive as new versions, deletes as tombstones, contested items as `federation.conflict`; gRPC `FederationSync` is refused; pulled items come back in recall, lexical match only, marked with their peer and trust 20 (0065) |
| Region lock (data residency)                    | 🔶 BETA   | With `MNEMO_REGION` set, a new workspace is pinned to it, and HTTP, dashboard, gRPC and WebSocket calls for another region's workspace are refused (403 `wrong_region`, `PermissionDenied`, close 1008); workspaces from before migration 0062 have no region and pass                                                                                                                                                                                                                                                                                  |
| Metrics endpoints                               | ✅ STABLE | `MNEMO_METRICS_TOKEN` bearer; 404 in production without a token                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Production guards                               | ✅ STABLE | The server refuses to start in production with `MNEMO_DASHBOARD_INSECURE_COOKIE` or `MNEMO_ALLOW_UNSAFE_DB_ROLE` set to `true`                                                                                                                                                                                                                                                                                                                                                                                                                          |

## Not there yet

- **Releases from git.** `types` 3.6.2, `client-ts` 3.6.3, `mcp` 3.6.4 and `cli` 3.6.5 are not on
  npm yet and must be published in that order; see [`RELEASING.md`](RELEASING.md).
- **CI.** The workflows exist in `.github/workflows/` but GitHub Actions is off.
- **SDK distribution.** No PyPI package, no Go module tag.
- **`full` host capture.** No host build has transcript and deletion proofs.
- **Pin priority in recall** (see Pinning above).

What is planned next is in [`../ROADMAP.md`](../ROADMAP.md).
