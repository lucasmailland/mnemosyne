## Executive Summary

The stdio runtime registers **33 unique tools**. B6.28-B6.30 are complete: one
private ordered registrar array drives runtime and every full-registry suite;
33 normalized input artifacts match the built stdio wire; 95 executable
handler baselines cover every effective output/error variant; and one composed
strict+runtime gate runs in CI with explicit Turbo build ordering. B6.31 runtime
version alignment remains open. Every public name below remains owned by its
handler's `server.registerTool("memory_*", ...)` call.

The highest-risk findings are:

1. Accepted intent is silently lost in `memory_remember`, recall temporal/search
   controls, session fields, forget reasons, and some sensitivity paths.
2. `memory_event.archive` reports success for an immutable no-op, and task
   delegation bypasses the dedicated provenance/policy route.
3. `memory_skill.create` and `.list` do not share a proven primitive-kind path.
4. B6.31 remains open: package version `3.6.0-alpha.0` still disagrees with the
   handshake/User-Agent fallback version `2.0.0-alpha.0`. B6.29-B6.30 closed
   normalized schema artifacts, executable output baselines, and composed CI.
5. Concrete repository consumers constrain the server key, environment names,
   launch command, 27 exact plugin tool names, and selected fields. They do not
   justify preserving silent drops or false-success behavior.

Recommended order: B6.3-B6.5 plus B6.7/B6.35, B6.8-B6.27, then
B6.31-B6.33.

## How To Read This Audit

Source precedence is runtime MCP schema, TypeScript SDK, HTTP route, core and
storage, executable tests, concrete consumers, then documentation. Tests prove
behavior but are not consumer-dependency evidence.

| Disposition   | Meaning                                                          |
| ------------- | ---------------------------------------------------------------- |
| `persisted`   | Reaches the promised durable state without semantic loss.        |
| `transformed` | Intentionally renamed, defaulted, narrowed, or mapped.           |
| `read-only`   | Affects retrieval/presentation and should not persist.           |
| `rejected`    | Explicitly fails before the promised operation.                  |
| `dropped`     | Accepted at one boundary but silently omitted later.             |
| `output-only` | Returned or echoed without affecting the operation.              |
| `unresolved`  | Requires bounded runtime/database evidence after static tracing. |

| Compatibility      | Meaning                                                       |
| ------------------ | ------------------------------------------------------------- |
| `preserve`         | A concrete consumer depends on the current contract.          |
| `version`          | Correction would break a concrete consumer or durable format. |
| `correct directly` | Behavior violates its contract with no consumer dependency.   |
| `deprecate`        | Preserve temporarily while migrating a concrete consumer.     |
| `no evidence`      | Only tests, stale docs, snapshots, or assumptions mention it. |

| Remediation     | Meaning                                                      |
| --------------- | ------------------------------------------------------------ |
| `persist`       | Carry the field to its promised durable effect.              |
| `transform`     | Define and test the intentional mapping.                     |
| `reject`        | Fail unsupported behavior explicitly before side effects.    |
| `remove`        | Eliminate an unsupported field/action with no consumer need. |
| `deprecate`     | Migrate a concrete consumer through a bounded transition.    |
| `runtime proof` | Add the bounded evidence needed to resolve the trace.        |

Citations include stable symbols plus `path:line`. An unresolved entry must
name its last verified symbol, missing evidence, bounded proof, risk, and owner.

   recall `asOf` and personal-only intent, session labels/hint content/roles,

   delegation bypasses provenance/RBAC; consolidation correctly rejects deep
   and dry-run but manual fast mode omits replay validation. Transform/reject

   anticipation, composition, introspection, workflow, reasoning, doctor, and
   status `HealthSnapshot`; status/context hide unavailable dependencies.
   Stats has a separate synthetic zero/null fallback when its drift snapshot
   fails. Normalize under B6.23-B6.25.

   deferred to B6.23-B6.25; package/handshake/User-Agent versions, public docs,
